# Формат истории XFBAR001 и правила загрузки

## Проверенный формат

Файл начинается с фиксированной части заголовка длиной 60 байт, затем идёт UTF-8 имя инструмента и массив записей. Все многобайтовые числа в исследованном наборе имеют little-endian представление.

| Смещение | Тип | Поле |
|---:|---|---|
| 0 | `char[8]` | magic `XFBAR001` |
| 8 | `int32` | версия |
| 12 | `int32` | заявленный размер записи |
| 16 | `int32` | период в секундах |
| 20 | `int32` | количество знаков |
| 24 | `double` | размер пункта |
| 32 | `int64` | количество баров |
| 40 | `int64` | время первого бара, Unix seconds |
| 48 | `int64` | время последнего бара, Unix seconds |
| 56 | `int32` | длина UTF-8 имени инструмента |
| 60 | `byte[symbol_len]` | имя инструмента |

Начало данных вычисляется только как `60 + symbol_len`. Нельзя использовать `56 + symbol_len`.

Каждая запись `XFBAR001` занимает ровно 60 байт:

| Смещение | Тип | Поле |
|---:|---|---|
| 0 | `int64` | время открытия, Unix seconds |
| 8 | `double` | open |
| 16 | `double` | high |
| 24 | `double` | low |
| 32 | `double` | close |
| 40 | `int64` | tick volume |
| 48 | `int32` | spread в пунктах |
| 52 | `int64` | real volume |

## Обязательная валидация

Загрузчик `data_v2` проверяет magic, версию, длину имени, размер файла, число записей, период, конечные временные метки, строгий рост времени, конечность цен, `high >= max(open, close)`, `low <= min(open, close)`, неотрицательные объёмы и спред.

В части файлов акций заголовок ошибочно содержит `record_size = 1`, хотя полезная нагрузка состоит из 60-байтовых записей. Восстановление допустимо только при точном равенстве:

`payload_bytes == bar_count * 60`.

Такое чтение всегда сопровождается предупреждением. Оно не применяется к файлам с иной длиной или неоднозначной структурой.

`XFBAR002` имеет 260-байтовую запись: первые 60 байт соответствуют бару, затем следуют 25 значений `double`. Файлы `_IND` не используются как независимая ценовая история в текущем исследовании.

## Таймфреймы

Исходным каноническим рядом принят M5 (`period_seconds = 300`). Обнаруженные готовые M15/H1/H4 нельзя использовать: они построены последовательными группами по 3/12/48 строк и после пропусков календарно смещаются.

M15, H1 и D1 строятся заново из M5 по календарным UTC-корзинам. Для каждой корзины сохраняются число исходных M5-баров, признак неполноты и признак предшествующего разрыва. D1 допускает только заранее заданное смещение границы суток, кратное пяти минутам.

## Фактический пример GBPJPY

- путь: `D:\AHexaTrader\DataFiles\raw\GBPJPY\GBPJPY_M5.bin`;
- SHA-256: `76D780A5703C1AB14AA144AD30EB88EECF1D9E9946772D25072435275F378E97`;
- 70 007 M5-баров;
- период: 23 января 2025 16:55 UTC — 31 декабря 2025 23:55 UTC;
- 76 календарных разрывов;
- `digits = 3`, `point = 0.001`;
- median / p95 / p99 spread: 9 / 40 / 255 пунктов;
- real volume во всём файле равен нулю.

## Ограничение актуальности

Все 62 найденных M5-ряда заканчиваются около 31 декабря 2025 — 1 января 2026. На дату аудита 21 июля 2026 история отстаёт примерно на шесть с половиной месяцев. Перед любым решением о реальной торговле данные нужно обновить и выделить новый, действительно нетронутый будущий OOS.
